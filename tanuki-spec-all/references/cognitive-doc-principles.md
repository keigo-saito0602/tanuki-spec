# 認知科学に基づく資料構成の原則（正本）

このリポジトリの仕様書テンプレート（`spec-items.yaml`の`review_checklist`/`audience`/凡例、レンダラの体裁）と、
将来の汎用スキル `tanuki-doc-architect` は、すべてこの原則を実装したものである。原則を1箇所に集約し二重管理を防ぐ。

人が読む文章を出力するスキルは、出力前にこのファイルを読む。各スキルは`references/cognitive-doc-principles.md`のsymlinkでこの正本を参照する。

## 症状を二つに分ける（最初に読む）

「AIの文章が頭に入らない」は、原因が異なる二つの症状の混合である。対策の向きが逆なので、混ぜたまま直すと打ち消し合う。

| | ① 読むのが辛い | ② 頭に入らない、思い出せない |
| --- | --- | --- |
| 原因 | 外在的負荷が高い。一文が長い、硬い語が多い、構造が見えない | 浅い処理。なめらかに読めるため、読み手が意味づけをしないまま通過する |
| 対策 | 負荷を減らす（原則1〜26、文レベルの規範、語彙の規範） | 負荷を残す、あるいは加える（原則27〜34、想起を組み込む規範） |
| 判定 | 読み終わるまでに何度も戻る | 読み終えた直後に要点を言い直せない |

「難しい語で内容が入ってこない」は①である。ただし術語（その概念を指す標準の呼び名）を消すと意味が変わるため、術語と難語を分けて扱う。判断は「語彙の規範」に置いた。

認知負荷理論（原則1）は負荷を三つに分ける。**外在的負荷**は見せ方の下手さによる無駄な負荷、**内在的負荷**は内容そのものの難しさ、**本質的負荷**は理解を組み立てるために使う負荷である。

目標は「全部軽くする」ではない。**外在的負荷を削り、空いた容量を本質的負荷へ回す**ことである。読み手が楽になったかどうかは品質指標にならない（原則29）。

## 読み手モデル（最重要）

- 要件定義書・プロダクトバックログ = 非技術者（クライアント・経営視点）。結論ファースト・平易・段階的開示。
- 基本設計書・詳細設計書 = 第三者の技術者。多視点レビュー（PBR）・トレース・ADR。

## 11原則

1. 認知負荷理論（Sweller）: 無駄な負荷（機械マーカー・著者メタ・重複・装飾）を本文から隔離する。
2. 段階的開示（Nielsen）: サマリ層→本論層→付録層の3層。
3. 結論ファースト（Minto/BLUF）: 文書・各節を結論文で始める。
4. スキャン読み（NN/g F-pattern/layer-cake）: 見出しと行頭に情報を凝縮する。
5. 合図・強調（Mayer Signaling/Von Restorff/Gestalt）: 強調は意味に固定し凡例で宣言する。
6. チャンク化（Miller 7±2）: 1リスト5〜7項目、見出しは3階層まで。
7. チェックリスト（Gawande）: 見落としがちな観点を節単位のチェックリストにする。
8. Perspective-Based Reading（Basili/NASA）: 役割視点別に読み多視点で網羅する。
9. トレーサビリティ（RTM）: 要件↔設計↔テストの対応で抜け・影響を可視化する。
10. ADR（Nygard）: 決定・代替案・トレードオフを1判断1レコードで記録する。
11. Plain Language: 短文・能動態・具体語、用語は用語集へ集約する。

## 深い理解と記憶の定着（原則27〜34）

1〜26で外在的負荷を削り切ったうえで適用する。番号は出典台帳の通し番号に対応する。

27. 流暢性の錯覚（Undorf）: なめらかに読めることを、理解された証拠として扱わない。読み手の「わかった」という感覚は記憶の予測因子ではない。
28. 望ましい困難（Bjork）: 想起や再構成を要求する困難は残す。削るのは、探し直し・読み返し・解釈の揺れといった無駄な困難だけである。
29. 楽さを品質指標にしない（Stadler他）: 読み手の負荷が下がっても、判断の質が下がるなら改悪である。文書の良否は、読後に読み手が下せる判断で測る。
30. 所有感を残す（MIT, プレプリント）: 結論を全部書き切ると、読み手にとって他人の文章になる。決定と根拠は示し、適用の判断は読み手側に残す。
31. 想起を要求する（Dunlosky他）: 想起練習は高効用、自己説明と精緻化質問は中程度、**要約とハイライトは低効用**である。要約の追加や太字の増加を定着策として採らない。
32. 既知から新規へ（given-new）: 段落と文は、読み手が既に知っている情報から始め、新しい情報を後半に置く。
33. 一文の長さを管理する（李在鎬他）: 日本語では一文の長さが可読性の主要因である。漢語の連続、一文中の動詞と接続助詞の数、指示語も難易度を上げる。
34. 原文の語彙を持ち越さない（LLM文の特性）: LLMは原文の語彙選択と修辞構造へ追従しやすい。表面はなめらかでも専門語と情報密度が原文のまま残る。専門語は初出で一度だけ言い換え、以後はその術語で通す。

## 文の長さと構造（原則35〜36）

原則33を「短くする」と読み替えないために置く。

35. 長さを揃えない（文長の変化）: 短文・中文・長文を混ぜたほうが、平均だけを下げた文章より読みやすい。均一な長さは、AI文の読みにくさとして現れる特徴でもある。長い文は許されるが、連続させない。
36. 係り受けの距離を詰める（Gibson, 依存局所性）: 処理の負荷は文の長さではなく、係り受け関係にある語の距離で決まる。距離が長いほどワーキングメモリを消費する。**長い文を短くするより、係り受けを近づけるほうが効く。**

## 文レベルの規範

数値は運用値であり、研究が示した閾値ではない。原則33と35に沿って「長さを管理する」ことを判定可能にするために置いている。

**上限は制約ではなく分布の目安である。** 長さを理由に情報を落とすほうが、長い文が残るより害が大きい。書類では特にそうなる。

- 一文の長さは**平均**40字前後に置く。個々の文を上限で切らない。
- 60字を超える文は、下の「長い文を許す条件」を満たすかどうかで判定する。満たすなら残す。
- 長い文を連続させない。長い文の前後には短い文を置く（原則35）。
- 一文に一つの主張だけを置く。長さではなく主張の数で割る。
- 見出し1つあたりの本文は7行以内。超えたら見出しを割る（原則6）。
- 指示語（これ、それ、この点）が指す対象は、同じ文か直前の文で特定できる状態にする。
- 語彙は下の「語彙の規範」に従う。硬いだけの語は置き換え、術語は残す。
- 強調は1画面あたり1箇所まで。強調が増えると合図として機能しなくなる（原則5）。
- 節の冒頭に「この節で決まること」を1文で置く（原則3）。

### 長い文を許す条件

長さそのものは負荷ではない。負荷を生むのは、係り受けの距離と、途中で保持させる要素の数である（原則36）。次をすべて満たす長い文は残してよい。

- 主語と述語の距離が近い。述語まで読まないと意味が確定しない構造にしない。
- 修飾の入れ子を作らない。修飾語が別の修飾語の中に入る形を避ける。
- 途中で読み手に保持させる要素が3つを超えない。
- 並列が3項以上になるなら、文ではなく箇条書きへ出す。
- 読点が意味の区切りと一致している。息継ぎのために打たない。
- 一文の主張が1つに保たれている。

条件を満たさない長い文は、二文に割るのではなく**構造を組み替える**。割ると主張が弱まる場合は、修飾を後置するか、並列を箇条書きへ出す。

### してはならない短縮

- 情報を落として字数を合わせる。
- 条件、例外、範囲の限定を削って断定へ変える（原則29と衝突する）。
- 数値の根拠や分母を削る。
- 一つの主張を二文に割り、接続を失わせる。

## 語彙の規範

読みにくい語には二種類ある。混同すると、消してはいけない語を消すか、直せる語を放置することになる。

| | 術語（専門用語） | 難語（硬いだけの一般語） |
| --- | --- | --- |
| 例 | 冪等性、結合テスト、正規化、トレーサビリティ | 鑑みる、齟齬、勘案、逐次、具備、遺漏 |
| 判断 | その概念を指す標準の呼び名であり、置き換えると意味が変わる | 平易な語で同じ意味を書ける |
| 扱い | **残す。** 初出で一度だけ平易な言い換えを添え、以後はその術語で通す（原則34）。用語集へ集約する（原則11） | **置き換える。** 例外なし |

難語の判断基準は「日常会話で使うか」である。使わない語は、意味が同じ日常語へ置き換える。同義であれば高頻度語を選ぶ（原則33）。

- 鑑みる → 踏まえる、考えると
- 齟齬 → 食い違い、ずれ
- 勘案する → 考えに入れる
- 逐次 → 順に、ひとつずつ
- 具備する → 備える、持つ
- 遺漏 → 漏れ
- 惹起する → 引き起こす
- 漸次 → 少しずつ
- 担保する → 保証する、守る
- 資する → 役立つ
- 平仄を合わせる → そろえる
- 蓋然性 → 確からしさ
- 上記に準ずる → 上と同じにする

表は網羅ではなく判断例である。表にない語も、上の基準で判断する。

あわせて、次の癖を直す。いずれも語を難しくせずに文を重くする。

- 「〜を実施する」「〜を行う」を「〜する」へ縮める。
- 漢語のサ変名詞を連ねない（例「要件定義書作成作業実施」→「要件定義書を作る」）。
- 二字漢語を三つ以上続けない。
- 名詞化した動作を動詞へ戻す（例「削除の実行」→「削除する」）。

## 想起を組み込む規範

- 読み手の判断が必要な箇所では、選択肢と判断基準を示し、結論は書かない（原則30）。
- 文書末尾に「読み手が決めること」または確認3問のいずれかを置く（原則31）。
- 未確定事項は、なめらかな断定で埋めず、不足として明示する。
