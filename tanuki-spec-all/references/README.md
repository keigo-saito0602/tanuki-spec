# references — 参照仕様と出典の扱い

本ファイルは主に`tanuki-spec-generator`が生成時に使う参照仕様の扱いを説明する。

## 1. 生成時に参照する「過去仕様」（都度指定）

本SKILLは参照元を固定しない。生成のたびに、参照したい過去仕様の**必要な内容だけ**を入力として渡す。

- 入力には、仕様本文・画面説明・制約・判断理由など、今回の生成に必要な抜粋を含める。
- 無指定なら参照なしで、ユーザーストーリーのみから生成する。

参照仕様を使って埋めた項目は、項目脚注に**参照仕様（提供内容）**と、判断に使った要点を明記すること
（`SKILL.md` の②穴埋め生成ルール）。元資料のパス・ファイル名は記載しない。

## 2. 品質項目の出典（項目マスターの根拠）

`spec-items.yaml` の各項目 `source` フィールドが、採用した品質観点と資料内の位置を保持している。[`research/source-register.yaml`](../research/source-register.yaml) はその観点分類と位置指定の書式を定義する。原本のパス・ファイル名・版・ハッシュは管理しない。

| 観点分類 | 主な内容 |
| --- | --- | --- |
| 要件定義観点 | 要件定義の要点 |
| 設計観点 | 基本/詳細設計の要点 |
| 要件品質観点 | 要件定義の品質チェックリスト |
| 設計品質観点 | 設計の品質チェックリスト |
| 非機能観点 | 性能・可用性・セキュリティ等の非機能要求 |
| AI品質観点 | 生成AI開発の品質管理 |

> 根拠資料は第三者の著作物を含むため、本文および原本を特定できる情報はリポジトリに同梱しない。
> `spec-items.yaml` は各項目の「見出し・目的・品質観点の対応表」であり、原文の複製ではない。

## 3. Web調査の扱い

外部情報を品質基準へ採用する場合は、URL・取得日・採用理由・適用範囲を `research/` 配下へ記録する。一次情報（公式ドキュメント・原著論文）を優先し、本文の複製は保存しない。

## 4. ナレッジ蓄積（運用で育てる）

`evaluation/ai-quality-rubric.md §2⑤` に従い、生成の良否・気づきをこのフォルダに追記していく
（例: `learnings.md`）。溜まった知見は `spec-items.yaml` の項目追加/修正へ反映する。
