# 説明HTMLの配色規約

配色は装飾ではなく、読み順と意味を補助するために使う。
色を見分けられなくても、文字・形・境界線・配置から同じ意味を理解できる状態を必須とする。

## 基本方針

通常の説明ページは、次の3系統を中心にする。

1. **ベース約75%**: 淡い青灰色の背景、白い本文面、濃い灰色の本文
2. **メイン約20%**: 見出し、リンク、フロー番号に青
3. **アクセント約5%以下**: 本当に注意が必要な箇所だけに橙または赤

Coneの配色資料が示す「3色」「75:20:5」「濃淡で展開」を、Web文書の役割トークンへ置き換えたものとする。
成功・警告・危険などの状態色は意味がある場合だけ追加し、装飾色として数えない。

- [プレゼン資料における配色の基本 — Cone](https://cone-c-slide.com/see-sla/blog/document-color-usage/)（確認日: 2026-07-29）

## Zennから採用する見え方

Zennの記事画面を参考に、本文の可読性を優先して次を採用する。

- ページ背景は淡い青灰色
- 本文面は白
- 本文は真っ黒ではなく濃い灰色
- リンクと現在位置は青
- 境界線は低彩度の青灰色
- コードは濃紺の面に明るい文字
- 大きな装飾面を増やさず、余白と見出しで階層を示す

## コントラストと識別

- 通常文字は背景とのコントラスト比`4.5:1`以上を必須とする。
- 大きな文字と重要な非テキスト境界は`3:1`以上を必須とする。
- `--line`は装飾的な区切りだけに使い、カードや表の外周など認識に必要な境界には`--line-strong`を使う。
- ブランド色の面に載せる文字は、固定の白ではなく`--brand-contrast`を使う。
- 本文と主要見出しは可能なら`7:1`以上を目標とする。
- リンクは色だけでなく下線でも示す。
- 警告・成功・危険は「注意」「成功」「エラー」などの文字、アイコン、境界線を併用する。
- フローやグラフは凡例、ラベル、線種、形を併用する。
- フォーカスは色変更だけにせず、太さのある外枠を表示する。

根拠:

- [WCAG 2.2 Contrast Minimum](https://www.w3.org/TR/WCAG22/#contrast-minimum)
- [Understanding Use of Color — W3C WAI](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- [Using color — U.S. Web Design System](https://designsystem.digital.gov/design-tokens/color/overview/)

## グラフで複数系列を使う場合

系列色は通常のブランド色とは別に、カラーユニバーサルデザイン推奨配色を候補にする。
色だけで系列を区別せず、直接ラベル、形、線種、パターンを併用する。
黄色など白背景で見えにくい色は、線や文字には使わず、濃い境界線を持つ面に限定する。

- [カラーユニバーサルデザイン推奨配色セット](https://jfly.uni-koeln.de/colorset/)（確認日: 2026-07-29）
- [CUDO 推奨配色セットの説明](https://cudo.jp/?page_id=1565)（確認日: 2026-07-29）

## 禁止

- 白背景の通常文字へ`#3ea8ff`を使う。
- 複数の鮮やかな色を同じ重要度で並べる。
- 赤と緑だけで良否を区別する。
- 薄い灰色の文字を、必須情報や小さい文字へ使う。
- 背景色だけで情報の種類を伝える。
- コントラスト未検証のブランドカラーをそのまま本文へ使う。
